# Multiplayer consumer API

Crucible 0.3.1 retains registry API 0.1 and resource API 1.0. Network protocol 1.0 and asynchronous resource API 2.0 are additive. Each participating profile/server installs one core package, containing Crucible.dll, Crucible.Core.dll and Crucible.Contracts.dll. Consumers reference these assemblies without bundling copies and declare EveryoneMustHaveMod/Minor and versioned hard dependencies. Optional siblings are discovered through typed capabilities; local discovery is never evidence of remote support.

Register typed operations with `Plugin.Services.Operations.Register(owner, descriptor, codec, handler, recovery)`. The native request client looks up the same owned codec via the operation ID and exact request/reply types. Dispose registrations on unload; GUID reuse cannot revive an earlier handler or task. Invoke `Plugin.RequestClient.InvokeAsync<TRequest,TReply>` on the Unity thread, retain the task and inspect completion from Update. Task continuations are asynchronous and must never touch Unity objects.

Transport callbacks enqueue work. Authority handlers run in Crucible's Update pump and receive authenticated sender/actor/admin facts from the actual native connection. Payload context fields are correlation claims only. Validate consumer policy, current actor, permissions and target state before `MarkDecisionMade`. Single-player uses the same router in process. Remote negotiation proves the current server connection with a fresh challenge before adopting its epoch. Old world/epoch/generation replies cannot complete current tasks.

On the current native build, remote actor resolution uses the peer's character ZDO: the object must belong to that peer's native UID, represent the native Player prefab, and contain a nonzero vanilla player-ID value. The legacy peer PlayerID field is cross-checked when present; it is not a required identity source because this game build registers that RPC without sending it. Missing/mismatched objects fail closed. Initial Jötunn synchronization is observed against the current native RPC before its readiness latch is set, so an event delivered before the next Unity frame cannot be discarded as an old connection.

Payload limit: 16384 bytes. Pending limits: 32 per peer and 256 per session. Undispatched requests expire at ten monotonic seconds. Completed identities are held by `RequestLedger` for 120 monotonic seconds after they complete (clients stop retrying after ten), so an identical duplicate inside that window reuses the stored result and never executes again; after it the identity is pruned and Status answers UnknownRequest/UnknownCommand. Under pressure a completed identity may leave earlier, never before 30 seconds: an actor holding 1024 younger completed identities is refused with LedgerCapacity (only that actor), and admission refuses when 4096 entries are held with none past 30 seconds (peer commands count unresolved receipts toward the 4096). Unresolved decisions are never evicted. No wire format changed. Duplicate identical envelopes reuse the result only while their original registration remains active; conflicts or replacement owners reject. Cancellation before decision releases undecided work. After decision, lost transport/cancellation is RecoveryRequired or an explicit reconciled result, never an automatic refund. Supply a recovery callback that consults the consumer ledger without rerunning the operation. Core does not implement storage allocation or persistence.

Recovery may return a polling continuation. Crucible binds that continuation to the current same-world authority generation while preserving its original request identity; a later world/session change stops its old poll. Disposing an operation leaves a replay tombstone, but a replacement registration cannot receive the old operation's cached reply or re-execute its identity. Status for an inactive operation omits its reply. The native pump processes local cancellation before dispatching queued handlers.

Resource v1 signatures are preserved from the committed ExtraPotions contract. V2 uses immutable AsyncResourceContext and Task-returning provider/reservation interfaces. A held or decided result always carries a reservation. Dispose releases only undecided holds; CommitPending/RecoveryRequired entries remain owned by the provider's durable ledger. Each provider must verify its actual transaction and recovery behavior separately.

Bind Server policy using ConfigScope.ServerAuthoritative; local language, layout and personal intent use Local. `MeadworksConfig.CanEdit` separates authority readiness from admin status. Synced non-admin clients can consume policy but cannot edit it. Main menus have no gameplay authority. Always validate schema before binding settings. Jotunn restores local values on disconnect; test native sync and disconnect for each consumer.

Dedicated startup must initialize configuration, registration and authority handlers before any client renderer. Do not construct map/UI/fonts or local movement services on a dedicated server. Test single-player, a real host with a remote client, and a dedicated server with two distinct real client identities. Portable unit tests and metadata checks do not establish gameplay compatibility.

## Authority commands to native owners

Crucible 0.3.1 adds `Plugin.Services.PeerCommands.Register(owner, descriptor, codec, handler)` and `Plugin.PeerCommandClient.SendAsync<TCommand,TReply>(nativePeerId, commandId, correlationId, command, cancellation)`. Register the same typed command on authority and participants, retain its disposable registration, and call/observe tasks from Unity Update. Only a current server may send; peer identity comes from the native connection rather than the player character ID. Local single-player/host owners use the same command router. A dedicated authority does not need a local Player to send to remote owners.

The separate owner protocol 1.0 carries the exact application protocol. It binds each recipient's native ID and fresh connection nonce after the existing server epoch is authenticated. Only the current native server RPC can invoke remote handlers; replies must come from the exact target RPC and binding. Registration replacement, disconnect and stale generations hide cached replies. Status/cancel requests also match command, protocol and connection before accessing an existing receipt. Idle bindings send no new command identities.

Application request/reply limit is 16384 bytes; reply metadata has a bounded wrapper. Text is at most 128 characters, encoded text at most 512 bytes, and frames at most 65536 bytes. Each native connection admits at most 128 incoming frames per second. Pending commands are bounded at 32 per owner and 256 per session, retained identities strictly at 4096 including uncertain outcomes, and queued/pending work expires after ten monotonic seconds. Original handlers execute once; status polls reuse that identity. The sender returns RecoveryRequired when remote completion cannot be ruled out, including lost connections, cancellation and malformed success replies. A consumer's durable transaction/receipt protocol determines reconciliation; Crucible neither allocates inventory nor grants a refund.

## Shared capability contracts

Capabilities resolve by id, major version and the exact contract `Type` (`CapabilityRegistry.TryResolve<T>`). A product that shares a capability with another product uses a BCL delegate shape (`Func<...>`, `Tuple<...>`), identical in every assembly, so neither product references the other. Product-owned contracts keep their id constants in the product (for example `meadworks.containers.role` and `meadworks.containers.feed_source` in Burrow `Integration/IntegrationContracts.cs`, `meadworks.larder.foodslots.count` in Larder). When a contract needs shared bounds or a typed reader, Crucible ships it in `Crucible.Contracts.dll` (namespace `ExtraPotions.Meadworks.Contracts`), which every profile already installs.

| Id | Version | Provider | Consumers | Delegate type | Defined in |
| --- | --- | --- | --- | --- | --- |
| `meadworks.ember.sleep` | 1.0 | Ember | Cairn (sleep line next to its clock) | `Func<Tuple<bool,int,int,int,double,bool,float>>` | `src/Crucible.Contracts/EmberSleep.cs` (`EmberSleepContract`, `EmberSleepState`) |
| `meadworks.explore.radius` | 1.0 | Keel | Cairn (sea explore radius) | `Func<float>` | `src/Crucible.Contracts/Explore.cs` (`ExploreRadiusContract`) |
| `meadworks.explore.current` | 1.0 | Cairn | Keel (ship panel radius line) | `Func<float>` | `src/Crucible.Contracts/Explore.cs` (`ExploreCurrentContract`) |
| `meadworks.weather.events` | 1.0 | Tempest | Cairn (time and weather HUD warning) | `Func<Tuple<int,int,float,int,bool,int>>` | `src/Crucible.Contracts/WeatherEvents.cs` (`WeatherEventsContract`, `WeatherEventState`, `WeatherEventKind`, `WeatherEventPhase`) |

`meadworks.ember.sleep` 1.0 tuple items, in order: window open; players counted (0 to 1024); sleeping (at most players); required for the full skip (at most players); extra time rate (finite, 0 to 30; above zero is boosting); full skip running; full skip progress (0 to 1). The bounds match Ember's `meadworks.ember.sleep.state` peer command reply. Ember registers `AddCapability<Func<Tuple<bool,int,int,int,double,bool,float>>>(EmberSleepContract.Id, EmberSleepContract.ContractVersion, () => EmberSleepContract.Pack(state))`. Cairn resolves the same type with `EmberSleepContract.ContractVersion` as the minimum and reads through `EmberSleepContract.TryRead(provider, out var state)`, which gives false and the closed state when the provider is absent, throws or replies out of bounds. Both sides call it on the Unity main thread. Any new field is a new major version.

`meadworks.explore.radius` 1.0 is the local player's sea exploration factor: Keel returns `1 + share(Exploration Radius At 100, Sailing level)` while the local player is aboard a ship, else exactly 1. The delegate takes no argument because `Crucible.Contracts` has no game reference; the provider reads the local player itself. A valid factor is finite and in (0, 16]. Cairn reads it through `ExploreRadiusContract.ReadFactor(provider)`, which gives the neutral factor 1 when the provider is absent, throws or replies out of bounds, and multiplies it into its sea radius before its clamp. Keel stops its own fallback patch while Cairn runs.

`meadworks.explore.current` 1.0 is Cairn's current computed exploration radius in metres for the local player (land or sea radius after every factor and the clamp), finite and in [0, 10000]. Keel's ship panel reads it through `ExploreCurrentContract.TryRead(provider, out var metres)` and, on false, shows the vanilla radius times its own factor. Both explore contracts use the same delegate type and differ by id.

`meadworks.weather.events` 1.0 tuple items, in order: kind (`WeatherEventKind`: 0 None, 1 Blizzard, 2 Thunderstorm); phase (`WeatherEventPhase`: 0 Idle, 1 Warning, 2 Active, 3 Clearing); seconds left in the phase (finite, 0 to 3600); eligible biomes as `Heightmap.Biome` flag bits (never negative); whether the biome under the local player gets the event now; revision. Idle has kind None, 0 seconds, no biomes and is never affected; any other phase has a kind. Tempest holds one shared event at a time and increments the revision whenever kind, phase or biomes change; that counter is the change event (a consumer redraws when it differs from the one it last saw; the countdown alone does not bump it). Cairn reads through `WeatherEventsContract.TryRead(provider, out var state)`, which gives false and the idle state when the provider is absent, throws or replies out of bounds; while it shows the warning, Tempest hides its own badge. New fields or kinds are a new major version.
